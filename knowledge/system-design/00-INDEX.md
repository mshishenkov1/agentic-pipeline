# База знаний по системному дизайну

Справочная библиотека для `architect-agent` и `intake-agent`. Не промпт — материал, который агент читает по мере необходимости.

## Как этим пользоваться

**`intake-agent`** читает `02-требования-и-нфт.md` целиком перед первым раундом вопросов и `03-числа-и-оценка.md` — чтобы понимать, какие числа надо вытащить из человека.

**`architect-agent`** обязан прочитать перед проектированием:
- `01-процесс-проектирования.md` — порядок работы, включая обязательный вопрос о платформе;
- `08-критерии-решений-и-adr.md` — как выбирать между вариантами и что требует ADR;
- `09-диаграммы.md` — обязательный комплект схем и синтаксис;
- `14-выбор-языка-и-стека.md` — язык по каждому компоненту предлагает архитектор;
- `10-документация-arc42.md` — формат выходных артефактов.

Остальное — по теме задачи. `11-чеклист-ревью.md` читает `review-agent`.

## Принципы, которым подчинена вся база

1. **Проектируем под требования, а не под представление о «правильной» архитектуре.** Компонент без требования — дефект.
2. **Запас на 10×, переписывание на 100×.** Ни один из гигантов не начинал с текущей архитектуры. Задача — не построить сразу гиперскейл, а не закрыть себе дорогу к нему.
3. **Каждое решение имеет цену. Если не можешь назвать, чем платишь, — решение не обосновано.**
4. **Порядок вмешательства всегда от дешёвого к дорогому:** запросы и индексы → денормализация → вертикальное масштабирование → кэш → реплики → партиционирование → шардирование → мультирегион. Перепрыгивать ступени можно только с явным обоснованием в ADR.
5. **Наблюдаемость — часть архитектуры, а не эксплуатации.** Компонент без метрик и трассировки считается непроектированным.

## Источники

База собрана из:
- AWS Well-Architected Framework (шесть столпов: operational excellence, security, reliability, performance efficiency, cost optimization, sustainability), AWS Builders' Library, руководство AWS по cell-based architecture
- Azure Architecture Center, Cloud Design Patterns
- Google SRE Book и SRE Workbook, Google Cloud Architecture Framework
- «Designing Data-Intensive Applications» (Клеппман), «Release It!» (Найгард), microservices.io (Ричардсон)
- arc42, модель C4 (Саймон Браун), формат ADR (Найгард)
- Инженерные блоги: Discord, Figma, Slack, Uber, Netflix, Stripe, Shopify, Cloudflare
- Курс по System Design сообщества «Осознанная меркантильность» (конспект в `system-design-теория/`)

Числа в `03-числа-и-оценка.md` и кейсы в `case-studies/` проверены по первоисточникам в августе 2026. Утверждения, которые проверить не удалось, помечены явно.

Запусти полный конвейер агентной разработки для файла требований: `$ARGUMENTS`.

Ты — ORCHESTRATOR (правила в CLAUDE.md обязательны: сам не пишешь ни код, ни тесты; субагенты строго последовательно; перед каждым субагентом `python3 scripts/state.py agent <роль>`, после — `python3 scripts/check_zone_diff.py <роль> --since $REV`).

## 0. Инициализация
1. Проверь, что файл требований существует; иначе спроси человека.
2. Проверь окружение: существует `.venv` с dev-зависимостями (`.venv/bin/pytest --version`); если нет — создай: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"`.
3. `run_id` = слаг из имени файла + дата. Создай рабочую ветку `pipeline/<run_id>` от `main` и перейди в неё.
4. Обнови state.json: `run_id`, `requirements_file`, `branch`, `stage: "spec"`, запиши событие в history.

## 1. SPEC
1. Вызови субагента `spec-agent`, передав содержимое файла требований.
2. Если он вернул `needs_clarification` — задай каждый вопрос человеку через AskUserQuestion (`stage: "spec_questions"`), затем вызови spec-agent повторно с ответами.
3. Результат: `spec.md` + `acceptance-criteria.yaml`. Zone-diff-проверка роли `spec`. Закоммить артефакты.

## 2. DEV
1. Вызови `dev-agent`: задача — реализовать `spec.md` / `acceptance-criteria.yaml`. Не пересказывай ему ничего лишнего.
2. Zone-diff-проверка роли `dev`. Убедись, что он закоммитил изменения.

## 3. TEST
1. Вызови `test-agent`, передав ТОЛЬКО: пути `src/`, `spec.md`, `acceptance-criteria.yaml`. **Не передавай контекст dev-agent** (ни его отчёт, ни диспуты).
2. Zone-diff-проверка роли `test`. Зарегистрируй новые баги: `python3 scripts/state.py sync-bugs`. Закоммить тесты.

## 4. Фикс-цикл
Пока есть баги `status: open` (лимит итераций на баг — из `pipeline.config.yaml`):
1. Убедись, что `failing_test` бага реально падает (`commands.test_single`); иначе верни баг test-agent.
2. Вызови `dev-agent` с баг-репортом + спекой. Zone-diff. 
3. Вызови `test-agent`: верификация фикса (падавший тест + полный сьют). Zone-diff. `sync-bugs`.
4. Не зелено → инкремент итерации в баг-файле, повтор. Итерации исчерпаны → `status: "escalated"`, сводка человеку (что пробовали, почему не вышло, оставшиеся гипотезы), переходи к следующему багу.
5. Диспуты из `disputes/` копи до этапа ревью (или отдай review-agent сразу, если dev заблокирован спором).

## 5. REVIEW
1. Вызови `review-agent` (свежий контекст: пусть сам читает артефакты и diff от `main`).
2. `request_changes` → замечания с `assignee: dev` отдай dev-agent, с `assignee: test` — test-agent (по одному циклу, затем повторное ревью). Резолюции диспутов обязательны к исполнению.
3. Цикл ревью не более 3 раз, дальше — эскалация человеку.

## 6. GATES
1. `python3 scripts/run_gates.py --run-id <run_id>` — все шесть гейтов.
2. Красный гейт → верни соответствующему агенту (G1/G2/G3/G6 — обычно test или dev, G4 — dev, G5 — цикл ревью) и повтори. Не более 2 полных повторов, дальше эскалация.

## 7. Отчёт
Сформируй `reports/run-<run_id>.md`: реализованное; таблица багов (ID, severity, итерации, статус); эскалации со сводками; результаты гейтов; трассировка AC → тесты (из `scripts/check_ac_traceability.py`); метрики здоровья (среднее итераций/баг, mutation score, flake rate, срабатывания защиты от подгонки). `stage: "done"`. Закоммить всё в рабочей ветке и сообщи человеку итог. **Не мержи в main.**
